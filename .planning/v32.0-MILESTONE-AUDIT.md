## Recommendation

Two legitimate paths forward:

**Path 1: Close the gaps before archiving v32.0**
- Create a gap-closure phase (e.g., 213.1 or 214-closure) to convert the 16 buttons across the 7 files above
- This keeps v32.0 consistent with its stated goal ("sitewide")
- Downside: delays v33.0 Fee Service Decomposition kickoff

**Path 2: Accept as tech debt and archive v32.0 anyway**
- The milestone's PRIMARY value (4-tier CSS system + 90%+ rollout) is delivered
- The 16 missed buttons are functionally fine — they render correctly; they're just not using the new class names
- Track as tech debt in MILESTONES.md; address in a future cleanup quick task
- Downside: "sitewide rollout" ships without being truly sitewide, and the project accumulates the same kind of "rollout drift" the SeasonKey extraction was designed to catch

My recommendation is **Path 1** — the gap is small enough that closing it before archiving is cheaper than explaining later why "sitewide" didn't mean sitewide. The work is mechanical: 16 className string replacements, no logic changes, no tests needed.
