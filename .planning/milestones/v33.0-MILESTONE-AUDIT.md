**No integration checker agent spawned** — direct-style execution and
single-session context mean the person driving the refactor has
already verified integration at every step. Explicit verification:

1. **Service dependency graph** is acyclic (modulo the deferred
   closures that intentionally break the `FeeCalculator ↔
   FamilyGroupingService` and `FeeCache ↔ FeeCalculator` cycles at
   construction time).
2. **Every external caller** of a deleted `MembershipFees` method has
   been grep-verified and rewired: final grep for `\$fees->|\$membership_fees->|\$fees_service->|new MembershipFees` returned zero matches.
3. **Functions.php** no longer imports `Rondo\Fees\MembershipFees` — verified.
4. **PHP autoloader** (`composer dump-autoload -o`) regenerated successfully after the file deletion on both local and production.
5. **`FeeCacheInvalidator` is still registered** in `functions.php` bootstrap and its constructor now resolves deps from `FeeServices` — verified on prod post-deploy (caches flushed, snapshot still clean).

## End-to-end flows verified

All verified through the fee snapshot (which exercises the complete
fee calculation pipeline on 4,021 real persons):

- ✅ **Youth member with family discount** — `calculate_fee` → resolver category match → family grouping → `calculate_fee_with_family_discount` → stored discount meta used as fast path → verified by snapshot rows with non-zero `family_discount`
- ✅ **Non-youth member (senior/recreant/donateur)** — `calculate_fee` → resolver category match → no family discount applied → verified by snapshot rows in `senior`, `recreanten-walking-football`, `donateur`, `senioren-dames-vr30` categories
- ✅ **Former member in season** — `PersonFeeContext::is_former_member_in_season()` → fee snapshot tool skip logic
- ✅ **Settings round-trip** — REST fees endpoints read via `MembershipFeeSettings` → 101 option keys unchanged byte-for-byte across the milestone

## Tech debt accumulated

Two non-blocking items, both captured in the YAML frontmatter above
and worth tracking:

1. **`bin/deploy.sh` doesn't prune deleted files.** Phase 218 needed a
   manual `ssh + rm` to remove the orphaned `class-membership-fees.php`
   from the production theme. The recipe is in
   `.planning/phases/218-retire-membershipfees/NOTES.md`. Add a
   `--prune` flag or a post-sync cleanup hook so the next class-deletion
   phase doesn't hit this. Low priority — only matters when a phase
   deletes class files.
2. **Cosmetic doc-comment cleanup.** `FeeCalculator` still has a stale
   doc comment line referencing "MembershipFees god-class reference"
   even though the code now uses `PersonFeeContext`. Same in
   `FamilyGroupingService`. Pure doc housekeeping, not a blocker.

Neither item blocks milestone completion.
