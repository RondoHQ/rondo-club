<task type="auto">
  <name>Task 1: Create MolliePayment service class</name>
  <files>includes/class-mollie-payment.php</files>
  <action>
Create `includes/class-mollie-payment.php` in namespace `Rondo\Finance`. Mirror the structure of `class-rabobank-payment.php` but much simpler — MolliePayment is a pure service class with NO REST routes and NO constructor hooks.

The class has a single public method: `create_payment_link( int $invoice_id ): string|\WP_Error`

Implementation flow (in order):

1. **Validate invoice** — `get_post($invoice_id)`, check `post_type === 'rondo_invoice'`. Return `WP_Error('invalid_invoice', ...)` with status 404 if invalid.

2. **Idempotency check** — Read `get_post_meta($invoice_id, '_mollie_payment_id', true)`. If not empty, read `get_field('payment_link', $invoice_id)`. If BOTH exist and are non-empty, return the existing URL string immediately (no API call). If payment ID exists but URL is empty, fall through to create a new payment (handles partial write failures).

3. **Guard: API key configured** — `$config = new \Rondo\Config\FinanceConfig()`. Check `$config->get_mollie_api_key()` is not empty. Return `WP_Error('mollie_not_configured', __('Mollie API-sleutel niet geconfigureerd.', 'rondo'), ['status' => 400])` if empty.

4. **Load invoice data** — `get_field('invoice_number', $invoice_id)` and `get_field('total_amount', $invoice_id)`.

5. **Format amount** — `$amount_string = number_format( (float) $total_amount, 2, '.', '' )`. CRITICAL: Always use `number_format()` with 4 args to avoid locale issues. Never cast to string directly.

6. **Build payload** — Array with keys:
   - `amount` => `['currency' => 'EUR', 'value' => $amount_string]`
   - `description` => `'Factuur ' . $invoice_number`
   - `redirectUrl` => `home_url('/')`

7. **Conditionally add webhookUrl** — Check `get_site_url()` for `localhost` or `.local` using `strpos()`. If NEITHER is found, add `'webhookUrl' => rest_url('rondo/v1/mollie/webhook')` to payload. (The webhook endpoint is built in Phase 188; the URL format is correct.)

8. **Call Mollie SDK** — Wrap in try/catch for `\Mollie\Api\Exceptions\ApiException`:
   ```php
   $mollie_client = new MollieClient();
   $mollie        = $mollie_client->get();
   $payment       = $mollie->payments->create( $payload );
   ```
   On `ApiException`: `error_log()` the message, return `WP_Error('mollie_api_error', sprintf(__('Mollie betaling aanmaken mislukt: %s', 'rondo'), $e->getMessage()), ['status' => 502])`.

9. **Extract checkout URL** — `$payment->getCheckoutUrl()`. If empty/null, `error_log()` and return `WP_Error('mollie_no_checkout_url', __('Geen checkout URL in Mollie response.', 'rondo'), ['status' => 500])`.

10. **Store results** — `update_field('payment_link', $checkout_url, $invoice_id)` and `update_post_meta($invoice_id, '_mollie_payment_id', $payment->id)`.

11. **Return** — `return $checkout_url;`

Use imports at top of class file:
- `use Rondo\Config\FinanceConfig;` (for API key guard)
- No `use` for MollieClient — it's in the same namespace (`Rondo\Finance`)

File header pattern: Match `class-mollie-client.php` — PHPDoc block with `@package Rondo\Finance`, WordPress ABSPATH guard.

Error messages are in Dutch (matching `class-rabobank-payment.php` pattern: `'Ongeldige factuur.'`, `'Mollie API-sleutel niet geconfigureerd.'`, etc.)
