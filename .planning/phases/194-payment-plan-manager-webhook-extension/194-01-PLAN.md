**Create `includes/class-installment-payment-service.php`:**

Create a new class `Rondo\Finance\InstallmentPaymentService` with a single public static method:

```php
public static function create_payment( int $invoice_id, int $installment_number ): string|\WP_Error
```

This method extracts the logic from `PublicPaymentPage::create_installment_payment()`:

1. Read `_installment_plan`, `_installment_count`, and `_payment_token` from invoice post meta.
2. Calculate the amount:
   - If `_installment_{N}_amount` meta exists (multi-installment plans), use: `(float) _installment_{N}_amount + (float) _installment_{N}_admin_fee`.
   - If NOT found (full plan where write_installment_meta was not called): use `(float) get_field('total_amount', $invoice_id)` as the full amount (no admin fee for full plan).
3. Guard: Mollie API key must be configured (`FinanceConfig::get_mollie_api_key()`).
4. Build Mollie payment description:
   - Full plan: `'Factuur ' . $invoice_number`
   - Multi-installment: `'Termijn ' . $installment_number . '/' . $count . ' - Factuur ' . $invoice_number`
5. Build the Mollie payment payload with `amount`, `description`, `redirectUrl` = `home_url('/betaling/' . $token . '?betaald=1')`, and `metadata` with `invoice_id` and `installment_number`.
6. Conditionally add `webhookUrl` — omit on localhost/.local (same pattern as current code).
7. Create payment via `MollieClient`.
8. Store results: `_installment_{N}_mollie_payment_id`, `_installment_{N}_payment_link`, and reverse-lookup `_mollie_pid_{payment_id} = $installment_number`.
9. Return the checkout URL string on success, `\WP_Error` on failure.

The method must use `get_post_meta()` for all `_installment_*` keys (raw WP meta, NOT ACF). Only `total_amount` and `invoice_number` use `get_field()`.

**Extend `MollieWebhook::handle_webhook()`:**

Replace the existing step 5-8 (find invoice + transition) with a dual-path lookup:

**Path 1 — Installment reverse-lookup (new):**

After the `isPaid()` check (step 4), query for the reverse-lookup meta:

```php
$installment_posts = get_posts([
    'post_type'      => 'rondo_invoice',
    'post_status'    => 'any',
    'posts_per_page' => 1,
    'fields'         => 'ids',
    'meta_query'     => [
        ['key' => '_mollie_pid_' . $payment_id, 'compare' => 'EXISTS'],
    ],
]);
```

If found: extract `$invoice_id` and `$installment_number`, delegate to `$this->handle_installment_paid($invoice_id, $installment_number, $payment_id)`.

**Path 2 — Legacy full-payment lookup (existing, unchanged):**

If Path 1 returns empty, use the existing `WP_Query` on `_mollie_payment_id` meta. The existing idempotency check (`rondo_paid` status) and status transition (`wp_update_post` + `update_field`) remain unchanged. This preserves backward compatibility for invoices created before Phase 192-193.

**Add `handle_installment_paid()` private method:**

```php
private function handle_installment_paid( int $invoice_id, int $n, string $payment_id ): \WP_REST_Response
```

1. **Idempotency check:** If `_installment_{N}_status` is already `betaald`, return `['ok' => true]` immediately.
2. **Mark installment paid:** `update_post_meta($invoice_id, '_installment_' . $n . '_status', 'betaald')`.
3. **All-paid check:** Read `_installment_count` (cast to int, floor at 1). Loop from 1 to count. If ALL `_installment_{i}_status` values are `betaald`, the invoice is fully paid.
4. **If all paid:** Transition invoice: `wp_update_post(['ID' => $invoice_id, 'post_status' => 'rondo_paid'])` and `update_field('status', 'paid', $invoice_id)`.
5. **If NOT all paid:** Create payment for next installment (`$next = $n + 1`). Guard: only if `$next <= $count` AND `_installment_{$next}_mollie_payment_id` is empty (idempotency for N+1 creation). Call `InstallmentPaymentService::create_payment($invoice_id, $next)` inside a try/catch. If it fails, `error_log()` the error but do NOT propagate — the current installment's paid status is already saved.
6. **Return** `rest_ensure_response(['ok' => true])`.

**Key implementation details:**
- Use `get_post_meta()` for ALL `_installment_*` keys (raw WP meta, not ACF).
- Only `update_field('status', 'paid', ...)` uses ACF (the high-level invoice status string).
- The `handle_installment_paid` method handles the `full` plan correctly: `_installment_count = 1`, the webhook writes `_installment_1_status = betaald`, loop checks 1 iteration, finds `betaald` → marks invoice `rondo_paid`. This works because `update_post_meta` writes the status BEFORE the all-paid loop reads it.
- Always return HTTP 200.
