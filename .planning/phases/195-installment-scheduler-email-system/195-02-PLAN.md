  <action>
Create `includes/class-installment-email-sender.php` in the `Rondo\Finance` namespace. This class handles email composition and sending for installment-related emails. It is separate from `InvoiceEmailSender` (which handles discipline invoices with PDF, QR code, discipline table).

**Three public static methods**, all returning `true|\WP_Error`:

1. `send_installment_email( int $invoice_id, int $installment_number ): true|\WP_Error`
   - Creates a fresh Mollie payment link via `InstallmentPaymentService::create_payment( $invoice_id, $installment_number )`. If it returns `WP_Error`, return that error (do not send email without valid link).
   - Reads the `installment_email_template` from FinanceConfig.
   - Resolves template variables and sends email.
   - On success, writes `_installment_N_status = 'sent'` and `_installment_N_sent_at = current_time('mysql')`.

2. `send_reminder_1( int $invoice_id, int $installment_number ): true|\WP_Error`
   - Creates a fresh Mollie payment link (same as above — links expire, so each email needs a fresh one).
   - Reads the `reminder_1_email_template` from FinanceConfig.
   - Resolves template variables and sends email. No BCC.
   - On success, writes `_installment_N_reminder_1_sent_at = current_time('mysql')`.

3. `send_reminder_2( int $invoice_id, int $installment_number ): true|\WP_Error`
   - Creates a fresh Mollie payment link.
   - Reads the `reminder_2_email_template` from FinanceConfig.
   - Resolves template variables and sends email. Adds `Bcc:` header with `FinanceConfig::get_bcc_email()` if configured.
   - On success, writes `_installment_N_reminder_2_sent_at = current_time('mysql')`.

**Shared private helper method** `resolve_and_send( int $invoice_id, int $installment_number, string $template, string $checkout_url, string $subject_prefix, bool $add_bcc ): true|\WP_Error`:
   - Resolve person from invoice: `$person_id = get_field('person', $invoice_id)`. Validate person exists.
   - Build person name parts: `first_name`, `infix`, `last_name` from ACF fields on person.
   - Get person email from `contact_info` repeater (same pattern as `InvoiceEmailSender`).
   - Read installment meta: `_installment_N_amount`, `_installment_N_admin_fee`, `_installment_N_due_date`, `_installment_count`.
   - Format `termijn_bedrag` as Dutch currency: `'€ ' . number_format( $amount + $admin_fee, 2, ',', '.' )`
   - Format `vervaldatum` as Dutch long date: use `strftime`-style or manual: `intl` not guaranteed, so build manually from month names array: `['januari', 'februari', ..., 'december']` and format as `"25 november 2025"`.
   - Calculate `dagen_te_laat`: `max(0, floor((strtotime(current_time('Y-m-d')) - strtotime($due_date)) / DAY_IN_SECONDS))`
   - Format `betaallink` as HTML anchor: `<a href="..." style="color:#0891b2;text-decoration:underline;">Betaal nu</a>`
   - Template variable replacement via `str_replace()`:
     ```
     {naam}, {voornaam}, {factuur_nummer}, {termijn_nummer}, {totaal_termijnen},
     {termijn_bedrag}, {betaallink}, {vervaldatum}, {organisatie_naam}, {dagen_te_laat}
     ```
   - Build email subject: `$subject_prefix . ' - Factuur ' . $invoice_number . ' - ' . $org_name`
   - Build headers: `Content-Type: text/html; charset=UTF-8`, `From: $org_name <$contact_email>`, and conditionally `Bcc:` if `$add_bcc` and BCC email is configured.
   - Call `wp_mail()`. Return `true` on success, `WP_Error` on failure.

**Subject prefixes:**
- Initial send: `'Termijn ' . $installment_number`
- Reminder 1: `'Herinnering termijn ' . $installment_number`
- Reminder 2: `'Tweede herinnering termijn ' . $installment_number`

**Important notes:**
- Write status/timestamp BEFORE calling `wp_mail()` to prevent duplicates if the sweeper re-runs. If `wp_mail()` fails, the status is already 'sent' — this is acceptable (retry logic can be added later, and it prevents double-sends).
- Actually, for the INITIAL send: write `_installment_N_status = 'sent'` and `_installment_N_sent_at` BEFORE wp_mail. For reminders: write `_reminder_1_sent_at` / `_reminder_2_sent_at` BEFORE wp_mail.
- No PDF attachment, no QR code, no discipline table — this is a simple HTML email.
- Use `\Rondo\Fees\MembershipFees` to derive season from invoice post_date for any season-related needs, but for this class the variables come from stored installment meta (amount, due_date) so no season derivation is needed here.

**InstallmentScheduler (new file):**

Create `includes/class-installment-scheduler.php` in the `Rondo\Finance` namespace. Follow the `Calendar\Sync` cron pattern exactly.

1. Constants:
   ```php
   const CRON_HOOK      = 'rondo_installment_sweeper';
   const LOCK_TRANSIENT = 'rondo_installment_sweeper_lock';
   ```

2. Constructor:
   ```php
   public function __construct() {
       add_action( self::CRON_HOOK, [ $this, 'run_sweep' ] );
       add_action( 'after_switch_theme', [ $this, 'schedule_sweeper' ] );
       add_action( 'switch_theme', [ $this, 'unschedule_sweeper' ] );
   }
   ```

3. `schedule_sweeper()`: If not already scheduled, call `wp_schedule_event( strtotime('tomorrow midnight'), 'daily', self::CRON_HOOK )`.

4. `unschedule_sweeper()`: Get next scheduled timestamp, unschedule if exists.

5. `run_sweep()`:
   - Idempotency lock: check `get_transient( self::LOCK_TRANSIENT )`. If set, return early. Otherwise set transient with 5-minute expiry.
   - Wrap in try/finally to always delete transient.
   - Call `$this->process_invoices()`.

6. `process_invoices()`:
   - Query all invoices with active payment plans:
     ```php
     $invoices = get_posts([
         'post_type'      => 'rondo_invoice',
         'post_status'    => 'rondo_sent',
         'posts_per_page' => -1,
         'fields'         => 'ids',
         'no_found_rows'  => true,
         'suppress_filters' => true,
         'meta_query'     => [
             [
                 'key'     => '_installment_plan',
                 'value'   => 'full',
                 'compare' => '!=',
             ],
         ],
     ]);
     ```
   - For each invoice ID, call `$this->process_invoice( $invoice_id )`.

7. `process_invoice( int $invoice_id )`:
   - Read `_installment_count` meta.
   - Get today's date: `$today = current_time('Y-m-d')`.
   - Loop `for ( $n = 1; $n <= $count; $n++ )`:
     - Read `_installment_N_status`, `_installment_N_due_date`.
     - Skip if `empty($due_date)` (missing data — log warning).
     - Skip if `$status === 'betaald'` (already paid).
     - Calculate `$days_overdue = (int) floor( ( strtotime($today) - strtotime($due_date) ) / DAY_IN_SECONDS )`.

     **Decision tree:**
     - If `$status === 'pending'` AND `$today >= $due_date`:
       - Send initial installment email via `InstallmentEmailSender::send_installment_email( $invoice_id, $n )`.
       - Log result. If `WP_Error`, log and continue (sweeper will retry next day because status stays 'pending' — but the sender writes 'sent' before wp_mail, so if create_payment succeeded but wp_mail failed, status is already 'sent' and won't re-trigger. This is acceptable; a failed Mollie create_payment returns WP_Error and sender returns early without writing status, so it retries.)

     - Else if `$status === 'sent'` AND `$days_overdue >= 21`:
       - Check `_installment_N_reminder_2_sent_at`. If empty:
         - Call `InstallmentEmailSender::send_reminder_2( $invoice_id, $n )`.
         - Log result.
       (Check reminder 2 FIRST because >= 21 also satisfies >= 14. Skip reminder 1 if reminder 2 is due.)

     - Else if `$status === 'sent'` AND `$days_overdue >= 14`:
       - Check `_installment_N_reminder_1_sent_at`. If empty:
         - Call `InstallmentEmailSender::send_reminder_1( $invoice_id, $n )`.
         - Log result.

   Each email action should be wrapped in try/catch to prevent one invoice's error from stopping the entire sweep.
