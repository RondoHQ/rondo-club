  <name>Task 1: Create PhoneNormalizer class with E.164 normalization</name>
  <files>includes/class-phone-normalizer.php</files>
  <action>
Create `includes/class-phone-normalizer.php` with a `PhoneNormalizer` class in the `Rondo` namespace.

In `__construct()`, register 4 ACF update_value filters — one for each phone field:
- `acf/update_value/name=mobile_1`
- `acf/update_value/name=mobile_2`
- `acf/update_value/name=telephone_1`
- `acf/update_value/name=telephone_2`

All 4 filters point to the same handler method: `normalize_phone_number( $value, $post_id, $field, $original )`.

The `normalize_phone_number` method:
1. If `$value` is not a string or is empty, return `$value` unchanged.
2. Strip all Unicode invisible characters (same regex as formatPhoneForTel in JS: \u200B-\u200D, \uFEFF, \u200E, \u200F, \u202A-\u202E).
3. Trim whitespace.
4. If empty after cleaning, return empty string.
5. If already starts with `+` — strip all non-digit chars except leading `+`, return as-is (already international).
6. If starts with `00` — treat as international: strip `00` prefix, prepend `+`, strip non-digits from rest.
7. If starts with `0` (Dutch local number) — strip leading `0`, prepend `+31`, strip non-digits from rest.
8. Otherwise return the cleaned digits only (edge case, shouldn't normally happen).

This handles all Dutch input formats:
- `06-12345678` -> `+31612345678`
- `0612345678` -> `+31612345678`
- `06 1234 5678` -> `+31612345678`
- `020-1234567` -> `+31201234567`
- `+31612345678` -> `+31612345678` (unchanged)
- `+49 123 456789` -> `+49123456789`
- `0031612345678` -> `+31612345678`
- `` -> `` (empty unchanged)
