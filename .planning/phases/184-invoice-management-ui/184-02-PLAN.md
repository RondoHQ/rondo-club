**Create `src/pages/Finance/Facturen.jsx`** — Invoice list page:

Follow FeedbackList.jsx patterns for structure. Use Dutch labels throughout.

1. **Imports:** React hooks (useState, useCallback, useMemo), react-router (Link, useSearchParams), lucide-react (Receipt, Filter, FileText), useInvoices hook, useDocumentTitle, format from dateFormat, formatCurrency from formatters, PullToRefreshWrapper.

2. **Status configuration** — Reuse the established pattern:
   - Status colors: draft=gray, sent=blue, paid=green, overdue=red (same as FinancesCard StatusBadge)
   - Status labels: draft='Concept', sent='Verstuurd', paid='Betaald', overdue='Verlopen'
   - StatusBadge inline component (same pattern as FinancesCard)

3. **Component:** `export default function Facturen()`
   - `useDocumentTitle('Facturen')`
   - URL-based status filter via `useSearchParams` (default shows all invoices)
   - Fetch invoices: `useInvoices({ status: statusFilter || undefined })`
   - `PullToRefreshWrapper` with invalidation of `['invoices']` queries

4. **Header:** `<h1>` "Facturen" with `text-brand-gradient` class. No create button (invoices created from discipline cases).

5. **Filter bar:** Status filter dropdown with options: All (default empty), Concept (draft), Verstuurd (sent), Betaald (paid), Verlopen (overdue). Use same styling as FeedbackList filters.

6. **Invoice table** — Use a card with a table layout:
   - Columns: Factuurnummer, Lid, Bedrag, Status, Verstuurd, Aangemaakt
   - Sort: Client-side sorting with `useMemo`. Default sort by created date descending.
   - Sortable column headers (click to toggle asc/desc) with visual indicator. Use a `sortConfig` state with `{ key, direction }`.
   - Each row is a `<Link>` to `/financien/facturen/${invoice.id}` with hover effect
   - Person name from `invoice.person?.name` (returned by API's `format_person_summary`)
   - Amount formatted via `formatCurrency(invoice.total_amount, 2)`
   - Status: StatusBadge component
   - Sent date: Format `invoice.sent_date` if present (ACF date format 'Ymd', parse with `parse` from dateFormat: `parse(invoice.sent_date, 'yyyyMMdd', new Date())` then format as `d MMM yyyy`), show '-' if null
   - Created date: Format `invoice.created` (WordPress post_date, use `new Date(invoice.created)` then format as `d MMM yyyy`)

7. **Empty state:** When no invoices match, show Receipt icon with "Geen facturen gevonden" message. No create button.

8. **Responsive:** On mobile, hide less important columns (Verstuurd, Aangemaakt) with `hidden sm:table-cell`. The table should scroll horizontally on very small screens.

**Create `src/pages/Finance/FactuurDetail.jsx`** — Invoice detail page:

Follow FeedbackDetail.jsx pattern for structure.

1. **Imports:** React hooks (useState), react-router (useParams, Link), lucide-react (ArrowLeft, Send, CheckCircle, RefreshCw, Download, FileText, User, Receipt, Calendar, CreditCard), useInvoice/useSendInvoice/useUpdateInvoiceStatus/useResendInvoice hooks, useDocumentTitle, format/parse from dateFormat, formatCurrency, prmApi (for PDF URL).

2. **Component:** `export default function FactuurDetail()`
   - Get `id` from `useParams()`
   - `useInvoice(id)` for data
   - `useSendInvoice()`, `useUpdateInvoiceStatus()`, `useResendInvoice()` for mutations
   - `useDocumentTitle(invoice?.invoice_number || 'Factuur')`

3. **Back navigation:** Link to `/financien/facturen` with ArrowLeft icon + "Terug naar facturen"

4. **Header section:** Invoice number as h1, StatusBadge next to it. Show person name as link to `/people/${invoice.person?.id}`.

5. **Info cards** — Two-column layout on desktop, stacked on mobile:
   - **Left card: Factuurgegevens** — Invoice number, status, created date, sent date (if present), due date (if present), payment link (if present, show as external link).
   - **Right card: Lid** — Person name (linked), person email (if in invoice data), total amount prominently displayed.

6. **Line items table:**
   - Header: "Regels"
   - Columns: Omschrijving, Bedrag
   - Each line item shows `item.description` and `formatCurrency(item.amount, 2)`
   - If item has `discipline_case`, show case details: dossier ID, match description, sanction
   - Footer row with total: "Totaal" + `formatCurrency(invoice.total_amount, 2)` in bold

7. **Action buttons** — Rendered based on invoice status:
   - **Draft (status === 'draft'):**
     - "Verstuur factuur" button (primary, Send icon) — calls `sendInvoice.mutate(id)` with loading state. Use `window.confirm('Weet je zeker dat je deze factuur wilt versturen?')` before sending.
     - "Download PDF" button (secondary, Download icon) — If `invoice.pdf_path` exists, open `prmApi.getInvoicePdfUrl(id)` in new tab. If no PDF yet, show "Geen PDF beschikbaar" disabled.

   - **Sent (status === 'sent'):**
     - "Markeer als betaald" button (primary/green, CheckCircle icon) — calls `updateInvoiceStatus.mutate({ id, status: 'paid' })` with confirm dialog "Weet je zeker dat je deze factuur als betaald wilt markeren?"
     - "Opnieuw versturen" button (secondary, RefreshCw icon) — calls `resendInvoice.mutate(id)` with confirm dialog
     - "Download PDF" button (secondary, Download icon)

   - **Overdue (status === 'overdue'):**
     - Same as Sent: "Markeer als betaald", "Opnieuw versturen", "Download PDF"

   - **Paid (status === 'paid'):**
     - "Download PDF" button only (secondary)
     - No other actions needed

8. **Loading states:** Show loading spinner on mutation buttons when `isPending`. Disable all action buttons while any mutation is pending. Show success toast via a simple inline success message that auto-hides after 3 seconds (use useState + setTimeout pattern).

9. **Error handling:** Show error message below action buttons if mutation fails, extracting error.response?.data?.message or fallback text.

10. **Date formatting:** ACF dates stored as 'Ymd' (e.g., '20260216'). Parse with: `parse(dateStr, 'yyyyMMdd', new Date())`. WordPress dates (invoice.created) use standard ISO-ish format, parse with `new Date(dateStr)`. Format all dates as `d MMM yyyy`.
