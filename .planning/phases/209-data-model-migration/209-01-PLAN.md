<task type="auto">
  <name>Task 2: Create WP-CLI migration command, deploy, and run migration</name>
  <files>includes/class-wp-cli.php</files>
  <action>
Add a new WP-CLI command `migrate_contact_to_fixed_fields` to the existing `RONDO_Migration_CLI_Command` class in `includes/class-wp-cli.php`.

**Migration logic:**

1. Query all person posts (post_type = 'person')
2. For each person, read the `contact_info` repeater via `get_field('contact_info', $post_id)`
3. Map repeater entries to fixed fields using this priority logic:
   - `contact_type === 'email'` → first occurrence → `email_1`, second → `email_2`
   - `contact_type === 'email2'` → if `email_1` is empty use that, else `email_2`
   - `contact_type === 'mobile'` → first → `mobile_1`, second → `mobile_2`
   - `contact_type === 'phone'` → first → `telephone_1`, second → `telephone_2`
   - All other types (website, linkedin, calendar, twitter, bluesky, threads, instagram, facebook, other) → SKIP (these are being dropped per requirements — social links are out of scope)
4. Only write fields that have values (don't overwrite existing fixed field values if already populated — idempotent)
5. Use `update_field()` to write the new fixed fields

**Options:**
- `--dry-run` flag: Show what would be migrated without writing
- `--verbose` flag: Show per-person details

**Output:**
- Count of persons processed
- Count of fields migrated
- Count of persons skipped (no contact_info or already migrated)
- If `--dry-run`: list of skipped contact types with counts (so user can verify social links etc. are intentionally dropped)

**After creating the command:**
1. Deploy to production using `bin/deploy.sh`
2. Run the migration with `--dry-run` first to verify
3. Run the actual migration
4. Verify a sample of records have correct data

Use SSH commands per CLAUDE.md:
```bash
source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp rondo migrate-contact-fields --dry-run"
```
Then without `--dry-run` for actual migration.
