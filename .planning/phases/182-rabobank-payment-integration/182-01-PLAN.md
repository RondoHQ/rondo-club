Create `includes/class-rabobank-oauth.php` in the `Rondo\Finance` namespace.

This class manages the complete OAuth 2.0 Premium authorization flow for the Rabobank Payment Request API.

**Base URLs** (from Rabobank developer docs):
- Sandbox: `https://api-sandbox.rabobank.nl`
- Production: `https://api.rabobank.nl`
- OAuth authorize (sandbox): `https://oauth-sandbox.rabobank.nl/openapi/sandbox/oauth2/authorize`
- OAuth authorize (production): `https://oauth.rabobank.nl/openapi/oauth2/authorize`
- Token endpoint (sandbox): `https://api-sandbox.rabobank.nl/openapi/sandbox/oauth2/token`
- Token endpoint (production): `https://api.rabobank.nl/openapi/oauth2/token`

**Constants and Configuration:**
- `OPTION_RABOBANK_TOKENS = 'rondo_rabobank_oauth_tokens'` — WordPress option key for encrypted token storage
- Scope: `payment-request` (the scope required for betaalverzoek API)
- Token refresh buffer: 300 seconds (refresh 5 min before expiry)

**Constructor:**
- Load FinanceConfig to get credentials
- Determine environment (sandbox/production) from credentials
- Set base URLs accordingly

**Methods to implement:**

1. `get_authorize_url(): ?string` — Build the OAuth authorize URL with params:
   - `response_type=code`
   - `client_id` from FinanceConfig credentials
   - `scope=payment-request`
   - `redirect_uri` = `rest_url('rondo/v1/rabobank/callback')` (our callback endpoint)
   - `state` = wp_create_nonce('rabobank_oauth') for CSRF protection
   - Returns null if credentials not configured

2. `handle_callback(string $code, string $state): bool|WP_Error` — Exchange authorization code for tokens:
   - Verify state nonce with `wp_verify_nonce($state, 'rabobank_oauth')`
   - POST to token endpoint with `grant_type=authorization_code`, `code`, `redirect_uri`, `client_id`, `client_secret`
   - Use `wp_remote_post()` with headers: `Content-Type: application/x-www-form-urlencoded`
   - On success: store tokens via `store_tokens()`, return true
   - On failure: return WP_Error with details

3. `get_access_token(): ?string` — Get a valid access token:
   - Load stored tokens via `get_stored_tokens()`
   - If no tokens, return null
   - If access token expired (or within 300s buffer), call `refresh_token()`
   - Return the access token string

4. `refresh_token(): bool` — Refresh the access token:
   - Load stored tokens
   - POST to token endpoint with `grant_type=refresh_token`, `refresh_token`, `client_id`, `client_secret`
   - Use `wp_remote_post()` with `Content-Type: application/x-www-form-urlencoded`
   - On success: update stored tokens (merge new access_token, new refresh_token if provided, new expires_in)
   - On failure: clear stored tokens (user must re-authorize), return false

5. `store_tokens(array $token_response): void` — Encrypt and persist tokens:
   - Extract: `access_token`, `refresh_token`, `expires_in`, `token_type`, `scope`
   - Add `stored_at` = `time()` for expiry calculation
   - Encrypt entire array using `CredentialEncryption::encrypt()`
   - Store in `update_option(self::OPTION_RABOBANK_TOKENS, $encrypted)`

6. `get_stored_tokens(): ?array` — Retrieve and decrypt stored tokens:
   - `get_option(self::OPTION_RABOBANK_TOKENS, '')`
   - If empty, return null
   - Decrypt with `CredentialEncryption::decrypt()`
   - Return array or null on failure

7. `is_token_expired(array $tokens): bool` — Check if access token needs refresh:
   - Calculate: `$tokens['stored_at'] + $tokens['expires_in'] - 300 < time()`
   - Return true if expired or within buffer

8. `is_connected(): bool` — Check if valid tokens exist:
   - Get stored tokens
   - Return true if tokens exist (even if expired — we can try to refresh)
   - Return false if no tokens at all

9. `disconnect(): void` — Remove stored tokens:
   - `delete_option(self::OPTION_RABOBANK_TOKENS)`

10. `get_base_url(): string` — Return API base URL for current environment.

**REST endpoints** — Register via `rest_api_init`:

a. `GET /rondo/v1/rabobank/authorize` — Returns `{ authorize_url: string }` (admin permission required)
b. `GET /rondo/v1/rabobank/callback` — OAuth callback endpoint (no permission check — Rabobank redirects here, but verify nonce in state param). On success, redirect to the finance settings page with `?rabobank=connected` query param. On failure, redirect with `?rabobank=error`.
c. `GET /rondo/v1/rabobank/status` — Returns `{ connected: bool, environment: string }` (admin permission required)
d. `POST /rondo/v1/rabobank/disconnect` — Clears stored tokens (admin permission required)

For the callback endpoint, since it's a browser redirect from Rabobank (not an AJAX call), the callback should:
- NOT use standard REST permission_callback (it's a redirect, not authenticated API call)
- Verify the state param (nonce) to confirm the request originated from this site
- After token exchange, use `wp_redirect()` to send user back to the app: `home_url('/financien/instellingen?rabobank=connected')` or `home_url('/financien/instellingen?rabobank=error&message=...')`
- Must `exit` after redirect

**In functions.php**, add:
- `use Rondo\Finance\RabobankOAuth;` import
- Instantiate `new RabobankOAuth();` inside the REST API loading block (where other REST classes are loaded)

  <files>includes/class-rabobank-payment.php, functions.php</files>
  <action>
Create `includes/class-rabobank-payment.php` in the `Rondo\Finance` namespace.

This class handles creating payment requests (betaalverzoeken) via the Rabobank API and provides a REST endpoint for invoices.

**Constructor:**
- Accept or create RabobankOAuth instance
- Register REST routes via `rest_api_init`

**Methods to implement:**

1. `create_payment_request(int $invoice_id): string|WP_Error` — Create a Rabobank betaalverzoek:
   - Load invoice data: invoice_number, total_amount, person (name)
   - Get access token from RabobankOAuth
   - If no token: return WP_Error('rabobank_not_connected', 'Rabobank is niet gekoppeld. Autoriseer eerst via Instellingen.')
   - Build request body (JSON):
     ```json
     {
       "amount": {
         "value": "25.00",
         "currency": "EUR"
       },
       "counterpartyName": "Jan Jansen",
       "description": "Factuur YYYY-TNNN",
       "expiryDate": "2026-03-15"
     }
     ```
   - Amount value: format as string with 2 decimal places from total_amount
   - counterpartyName: person's display name (post_title of the person post)
   - description: "Factuur " + invoice_number
   - expiryDate: due_date from invoice (ACF field), formatted as Y-m-d. If not set, calculate from payment_term_days
   - POST to `{base_url}/openapi/sandbox/payment-request/payment-requests` (sandbox) or `{base_url}/openapi/payment-request/payment-requests` (production)
   - Headers: `Authorization: Bearer {access_token}`, `Content-Type: application/json`, `X-IBM-Client-Id: {client_id}`
   - Parse response: extract `paymentLink` (or `links.paymentUrl`) from response
   - Store payment link on invoice: `update_field('payment_link', $payment_link, $invoice_id)`
   - Return the payment link string on success, WP_Error on failure

2. `get_api_path(): string` — Return the API path prefix based on environment:
   - Sandbox: `/openapi/sandbox/payment-request/payment-requests`
   - Production: `/openapi/payment-request/payment-requests`

**REST endpoint:**
Register `POST /rondo/v1/invoices/(?P<id>\d+)/payment-link`:
- Permission: `check_financieel_permission` (same pattern as other invoice endpoints)
- Calls `create_payment_request($id)`
- On success: returns updated invoice detail using format from Invoices class
- On error: returns WP_Error

**Important implementation details:**
- Use `wp_remote_post()` for HTTP calls (WordPress standard)
- Set timeout to 30 seconds for API calls
- Log errors using `error_log()` for debugging
- The Rabobank sandbox API may return mock responses — the code should handle both sandbox and real responses gracefully
- If Rabobank API returns an error response (HTTP 4xx/5xx), parse the error body and return a descriptive WP_Error

**In functions.php**, add:

- Instantiate `new RabobankPayment();` inside the REST API loading block, after RabobankOAuth
