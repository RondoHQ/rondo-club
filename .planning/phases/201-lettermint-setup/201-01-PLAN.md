<tasks>

<task type="auto">
  <name>Task 1: Deactivate Gravity SMTP and activate Lettermint on production</name>
  <files></files>
  <action>
Via SSH to production (using `.env` credentials), run WP-CLI commands to:

1. Deactivate Gravity SMTP:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp plugin deactivate gravitysmtp"
   ```

2. Activate Lettermint:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp plugin activate lettermint"
   ```

3. Verify the plugin states:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp plugin list --status=active --format=table"
   ```

Do these in a single SSH session or rapid sequence to minimize the window where no email transport is active. Note: between deactivation of Gravity SMTP and entry of the API token (Task 3), WordPress will fall back to PHP's built-in `mail()` function — this is acceptable for the brief transition period.

Do NOT enable any "force" options (`lettermint_force_email`, `lettermint_force_from_name`). The theme's email classes already set correct From headers.
  </action>
  <verify>
Run `wp plugin list` on production and confirm:
- `gravitysmtp` shows status `inactive`
- `lettermint` shows status `active`
  </verify>
  <done>Gravity SMTP is inactive and Lettermint is active on production WordPress.</done>
</task>

<task type="auto">
  <name>Task 3: Configure API token and send test email</name>
  <files></files>
  <action>
Using the API token provided by the user in Task 2, configure Lettermint on production via WP-CLI:

1. Set the API token:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp option update lettermint_api_token 'TOKEN_FROM_USER'"
   ```

2. Verify the token was stored:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp option get lettermint_api_token"
   ```

3. Verify logging is enabled:
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp option get lettermint_enable_logs"
   ```
   If not `1`, set it: `wp option update lettermint_enable_logs 1`

4. Send a test email to the user's email address (ask user which address to use if not obvious, or use penningmeester@svawc.nl as both sender and recipient for a simple self-test):
   ```bash
   source .env && ssh -p "$DEPLOY_SSH_PORT" "$DEPLOY_SSH_USER@$DEPLOY_SSH_HOST" "cd $DEPLOY_REMOTE_WP_PATH && wp eval 'var_dump(wp_mail(\"USER_EMAIL\", \"Lettermint Test - Rondo Club\", \"<p>This is a test email sent through Lettermint from the Rondo Club WordPress site.</p>\", [\"Content-Type: text/html; charset=UTF-8\", \"From: AWC Rondo <penningmeester@svawc.nl>\"]));"
   ```

The `wp_mail()` call returns `true` if the Lettermint plugin accepted the email (which means it was successfully posted to the Lettermint API). A `false` return indicates a configuration problem.
  </action>
  <verify>
The `wp eval` command returns `bool(true)`, confirming the test email was accepted by the Lettermint API.
  </verify>
  <done>API token is configured, logging is enabled, and a test email was sent through Lettermint.</done>
</task>
