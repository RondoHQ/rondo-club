Body — define the canonical 48-key allowlist as a hard-coded const array, then capture each key with get_option() + call get_all_settings():

1. Define `FINANCE_OPTION_KEYS` as a hard-coded PHP array with ALL 48 keys in alphabetical order (the 40 rondo_finance_* + 8 rondo_membership_pass_* listed in the <interfaces> block above). Alphabetical order is for stable diffs even if the source file is edited later.

2. Loud assertion: after building `$options`, assert `count($options) === 48`. If not, `fwrite(STDERR, ...)` + `exit(1)` with a message naming the actual vs expected count. This is the drift tripwire.

3. Instantiate FinanceConfig: check `class_exists('\Rondo\Finance\FinanceConfig')` first — if missing, STDERR + exit 1 (same pattern as bin/fee-snapshot.php lines 30-33 for FeeServices). 4. For each option in the allowlist, call `get_option($key, null)`. Store as `$options[$key] = $value;`. Use `null` as default so "not set in DB" is distinguishable from "empty string stored". Do NOT dereference serialized arrays — `get_option()` already unserializes, and we want the post-unserialize values to be diffable in JSON.

5. Sort both `$options` and `$rest_response` by key recursively so `jq -S` is not required for determinism (but the harness will still run `jq -S` for defense in depth). Use `ksort($options)` at the top level; for `$rest_response`, define a small recursive helper or rely on wp_json_encode ordering (WordPress option arrays like `rondo_finance_mollie_accounts` and `rondo_finance_rabobank_credentials` contain nested assoc arrays — ksort them recursively with a local `ksort_recursive($arr)` closure).

6. Build the envelope:
```php
$envelope = [
    'schema_version' => 1,
    'generated_at'   => gmdate( 'c' ),
    'site_url'       => home_url(),
    'option_count'   => count( $options ),  // MUST be 48 by assertion above
    'options'        => $options,           // 48 raw WP option values, key-sorted
    'rest_response'  => $rest_response,     // Full get_all_settings() output, key-sorted
];

This is acceptable.
- DO NOT write anything, send any email, create any post, fire any hook. Read-only means read-only. The only side effect permitted is STDOUT / STDERR output.
