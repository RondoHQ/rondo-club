<task type="auto">
  <name>Task 1: Create InvoiceEmailSender service class</name>
  <files>includes/class-invoice-email-sender.php, functions.php</files>
  <action>
    Create `includes/class-invoice-email-sender.php` in namespace `Rondo\Finance` as a static service class (same pattern as InvoicePdfGenerator).

    **Main method: `send( int $invoice_id ): true|\WP_Error`**

    Steps:
    1. Validate invoice exists and is rondo_invoice post type
    2. Get invoice data: invoice_number, person (ID), total_amount, line_items, payment_link, pdf_path
    3. Get person data using the same pattern as InvoicePdfGenerator:
       - Build full name from first_name, infix, last_name
       - Extract email from contact_info repeater (first entry with contact_type = 'email' or 'Email')
       - If no email found, return WP_Error('no_email', 'Geen e-mailadres gevonden voor dit lid.')
    4. Create FinanceConfig instance (instance methods, NOT static — follow InvoicePdfGenerator pattern from lines 57-58):
       `$config = new FinanceConfig();`
       Get email template: `$template = $config->get_email_template();`
    5. Replace template variables:
       - `{naam}` → person full name
       - `{factuur_nummer}` → invoice_number
       - `{tuchtzaken_lijst}` → build a text list of discipline cases from line_items (iterate line_items, for each: get discipline_case match_description and sanction_description from ACF, format as "- {match_description}: {sanction_description} — € {amount}" per line)
       - `{totaal_bedrag}` → Dutch currency format "€ XX,XX" using number_format($total_amount, 2, ',', '.')
       - `{betaallink}` → payment_link field value, or "Neem contact op voor betaalinformatie." if empty
       - `{organisatie_naam}` → `$config->get_org_name()`
    6. Build PDF attachment path: wp_upload_dir()['basedir'] . '/' . $pdf_path (only if pdf_path is set and file exists)
    7. Set email subject: "Factuur {invoice_number} - {org_name}" (using `$config->get_org_name()`)
    8. Set From header using `$config->get_contact_email()` and `$config->get_org_name()`: "From: {org_name} <{contact_email}>"
    9. Send via wp_mail($to_email, $subject, $body, $headers, $attachments)
       - $attachments is array with full PDF path if exists, empty array otherwise
    10. Return true on success, WP_Error on wp_mail failure

    **Wire into functions.php:**
    Add `use Rondo\Finance\InvoiceEmailSender;` import and load statement in the REST API block (alongside InvoicePdfGenerator).
  </action>

    **REST endpoint in class-rest-invoices.php:**

    1. Add `use Rondo\Finance\InvoiceEmailSender;` import at the top (next to InvoicePdfGenerator import)
    2. Register new route in `register_routes()`:
       ```
       POST /rondo/v1/invoices/(?P<id>\d+)/send
       callback: send_invoice
       permission_callback: check_financieel_permission
       args: id with validate_callback is_numeric
       ```
    3. Create `send_invoice( $request )` method that orchestrates the full send flow:
       a. Validate invoice exists and is rondo_invoice
       b. Check invoice is in draft status (post_status === 'rondo_draft'). If not, return WP_Error('invoice_not_draft', 'Alleen conceptfacturen kunnen worden verstuurd.', ['status' => 400])
       c. Generate PDF if not already generated: check pdf_path field — if empty, call InvoicePdfGenerator::generate($invoice_id). If that returns WP_Error, return it.
       d. Create payment link if Rabobank is connected: check if RabobankOAuth is_connected() returns true — if so, call RabobankPayment create_payment_link() method (use the existing REST endpoint logic pattern from class-rabobank-payment.php). If not connected, skip payment link (it's optional).
         - Import RabobankOAuth at top. Check connection: `$oauth = new \Rondo\Finance\RabobankOAuth(); if ($oauth->is_connected()) { ... }`
         - For payment link creation: `$payment = new \Rondo\Finance\RabobankPayment($oauth); $result = $payment->create_payment_request($invoice_id);` — RabobankPayment takes $oauth in constructor, create_payment_request is an instance method. If it returns WP_Error, log it but continue (payment link is non-blocking).
       e. Send email: call InvoiceEmailSender::send($invoice_id). If returns WP_Error, return it.
       f. Transition status to Sent: reuse existing update_invoice_status logic — set post_status to 'rondo_sent', update ACF status to 'sent', set sent_date to current_time('Ymd'), calculate due_date using FinanceConfig instance method: `$config = new FinanceConfig(); $config->get_payment_term_days()` (instance methods, NOT static — same pattern as InvoicePdfGenerator lines 57-58).
       g. Return updated invoice detail via format_invoice_detail().
