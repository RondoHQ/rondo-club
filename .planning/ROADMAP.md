### 🚧 v28.0 Membership Fee Invoicing (In Progress)

**Milestone Goal:** Enable clubs to invoice members for seasonal membership fees with Mollie payment plans — full payment, 3 installments, or 8 installments — replacing external billing systems like Nikki. Members select their plan on a public landing page, pay via Mollie, and receive automated installment emails and overdue reminders.

- [x] **Phase 192: Data Model Foundation** (1/1 plan) — completed 2026-02-18
- [x] **Phase 193: Public Payment Landing Page** (1/1 plan) — completed 2026-02-18
- [ ] **Phase 194: Payment Plan Manager + Webhook Extension** (1 plan) — Installment state machine, reverse-lookup webhook pattern, all-paid invoice transition
- [ ] **Phase 195: Installment Scheduler + Email System** — Daily cron sweeper, monthly installment emails, overdue reminders, email templates
- [ ] **Phase 196: Bulk Invoice Creation** — Async batched creation for all members, billing method toggle, progress tracking
- [ ] **Phase 197: Frontend Updates** — Facturen filters, installment timeline, Contributie Factureer action, Finance capability gating

## Phase Details

### Phase 192: Data Model Foundation

**Goal:** The invoice data model supports membership fees alongside discipline cases, with a defined installment storage schema and billing configuration that makes all downstream phases safe to build on.
**Depends on:** Nothing (builds on existing rondo_invoice CPT from v26.0/v27.0)
**Requirements:** INV-03, BILL-01, BILL-04, INST-01
**Success Criteria** (what must be TRUE):
  1. Existing discipline invoices are backfilled with `invoice_type = discipline` and continue to work exactly as before
  2. A new membership invoice can be created in the database with the correct type field without touching the existing invoice code paths
  3. Installment data (amount, status, due date, Mollie payment ID) can be stored and read as flat numbered post meta on a rondo_invoice post
  4. The reverse-lookup key pattern (`_mollie_pid_{payment_id} = installment_number`) is defined and documented before any payment IDs are stored
  5. Admin can configure a per-installment administration fee amount in Finance Settings and the value is stored in FinanceConfig
**Plans:** 1 plan

Plans:
- [ ] 192-01-PLAN.md -- ACF invoice_type field, FinanceConfig installment admin fee, MembershipFees billing method, WP-CLI backfill command

### Phase 193: Public Payment Landing Page

**Goal:** Members can open the link from their invoice email on their phone, see their invoice details without logging in, choose a payment plan, and be redirected to Mollie to pay.
**Depends on:** Phase 192 (invoice type and billing toggle exist)
**Requirements:** PAY-01, PAY-02, PAY-03, PAY-04, PAY-05, PAY-06, PAY-07, PAY-08
**Success Criteria** (what must be TRUE):
  1. A member who opens `/betaling/{token}` in an incognito browser sees their invoice details (amount, member name, season) without any WordPress login prompt
  2. The page shows the available payment plan options (full / 3 installments / 8 installments) based on what the admin has enabled, with the per-installment administration fee clearly displayed for multi-payment plans
  3. Selecting "Volledig betalen" redirects the member to Mollie and initiates payment of the full invoice amount
  4. Selecting a multi-installment plan stores the plan choice on the invoice and redirects the member to Mollie for the first installment payment
  5. The page renders correctly on a mobile phone (no horizontal scrolling, touch-friendly buttons)
  6. An invalid or expired token shows a clear Dutch error message rather than a blank page or WordPress 404
**Plans:** 1 plan

Plans:
- [ ] 193-01-PLAN.md — PublicPaymentPage class (rewrite rule, GET/POST handler, Mollie payment, mobile CSS) + functions.php wiring + deploy

### Phase 194: Payment Plan Manager + Webhook Extension

**Goal:** Each Mollie payment is correctly matched to the right installment, installment statuses update automatically when Mollie confirms payment, and the invoice is marked fully paid only when every installment is complete.
**Depends on:** Phase 192 (installment meta schema defined), Phase 193 (plan selection stores plan data on invoice)
**Requirements:** INST-02, INST-04
**Success Criteria** (what must be TRUE):
  1. When Mollie calls the webhook with a payment ID for the second or later installment, the correct installment status changes to "betaald" — not the first installment, not the invoice itself
  2. An invoice with 3 installments shows status "verstuurd" (not "betaald") after the first and second installments are paid; it transitions to "betaald" only when all three are confirmed by Mollie
  3. A full-payment invoice (no installments) continues to transition to "betaald" on the first Mollie webhook — existing behavior is preserved
  4. The webhook always returns HTTP 200 regardless of lookup errors, preventing Mollie retry storms
**Plans:** 1 plan

Plans:
- [ ] 194-01-PLAN.md — InstallmentPaymentService DRY extraction, dual-path MollieWebhook with installment handling + all-paid gating + N+1 payment creation

### Phase 195: Installment Scheduler + Email System

**Goal:** Members receive their installment payment emails automatically on the 25th of each scheduled month, with escalating overdue reminders if they don't pay, without any manual treasurer action.
**Depends on:** Phase 194 (installment state machine exists), Phase 193 (landing page exists to link to in emails)
**Requirements:** INST-03, REM-01, REM-02, REM-03, BILL-05, BILL-06, BILL-07
**Success Criteria** (what must be TRUE):
  1. On the 25th of a scheduled installment month, members with an unpaid installment due that day receive an email with a fresh Mollie payment link pointing to their landing page
  2. A member who has not paid 14 days after an installment due date receives a first reminder email automatically
  3. A member who has still not paid 21 days after the due date receives a second reminder email, and the treasurer receives a BCC copy of that email
  4. Admin can configure separate email templates for the initial invoice, installment follow-up emails, and overdue reminders via Finance Settings
  5. The scheduler uses a single daily WP-Cron sweeper (not per-invoice scheduled events) so the wp_options cron table does not grow unbounded with hundreds of individual scheduled events

### Phase 196: Bulk Invoice Creation

**Goal:** Admin can create concept membership fee invoices for all eligible members in one action without the request timing out, and can monitor progress until all invoices are created.
**Depends on:** Phase 192 (invoice type + schema), Phase 193 (landing page and token generation ready), Phase 194 (payment plan meta ready), Phase 195 (email system ready)
**Requirements:** INV-01, INV-02, INV-03 (type field used by bulk creator), INV-04, INV-05, BILL-02, BILL-03
**Success Criteria** (what must be TRUE):
  1. Admin can toggle the seasonal billing method between Nikki and Rondo invoicing in Finance Settings, and the Contributie page hides Nikki-specific columns when Rondo invoicing is active
  2. Admin can enable or disable the 3-installment plan and 8-installment plan per season in Finance Settings
  3. Clicking "Maak facturen" on the Contributie page starts bulk invoice creation and immediately returns a response — it does not hang for 30+ seconds
  4. Admin can see a progress indicator (e.g., "47 van 312 facturen aangemaakt") that updates without refreshing the page
  5. If bulk creation is triggered a second time for the same season, already-existing membership invoices for those members are skipped without creating duplicates
  6. Admin can also create a concept membership fee invoice for a single member directly from the Contributie page or their person record

### Phase 197: Frontend Updates

**Goal:** Treasurer can navigate the Facturen list efficiently using invoice type, payment plan, and overdue filters, can inspect the full installment timeline on each invoice, and non-admin finance users can access all of this without WordPress admin privileges.
**Depends on:** Phase 196 (bulk creation ships installment data into invoices), Phase 194 (installment statuses exist), Phase 195 (overdue state exists)
**Requirements:** INST-05, FACT-01, FACT-02, FACT-03, FACT-04, AUTH-01
**Success Criteria** (what must be TRUE):
  1. Admin can filter the Facturen list to show only membership invoices, only discipline invoices, or all invoices
  2. Admin can filter the Facturen list to show only invoices with a specific payment plan (volledig / 3 termijnen / 8 termijnen)
  3. Admin can filter the Facturen list to show only invoices with at least one overdue installment
  4. The invoice detail page shows a per-installment timeline: each installment with its due date, amount, status (openstaand / verstuurd / betaald / verlopen), and the date it was paid if applicable
  5. A user with the Finance capability (but not WordPress admin) can access the Facturen list, invoice detail, and Contributie page without being redirected or blocked
